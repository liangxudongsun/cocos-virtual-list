# 03 · 方案 B（占位 + AABB 可见性）与方案 C（分层渲染）详解

本文补全 SKILL 选型表里方案 B / 方案 C 的内部机制、取舍与已知限制，供需要落地这两类方案或排障时参考。方案 A 的算法细节见 `references/01`；刷新降频与速度自适应缓冲的策略见 `references/01 §9`。

## 方案 B：占位节点 + ShowNode 对象池

### 机制

- content 下**按数据量生成空占位节点**，只用对象池管理"可见内容 ShowNode"的挂载/回收；不计算 item 位置（占位节点由手动累计尺寸定位，也可配 Layout）。
- **可见性判断**：视口四边界（含 anchor 修正）vs 节点世界坐标 AABB；水平先判、短路垂直。
- **降频**：SCROLLING 事件计数器，每 3 次刷一次。

### 取舍

- 占位节点本身不占渲染（只是 JS 对象 + UITransform 的开销）；但每次刷新要做 O(cells) 的 AABB 检测（世界矩阵读取），cells 上千后仍然肉疼——这是方案 B 相对方案 A 的核心成本差异。
- 适合几百条、且团队想沿用 Layout/编辑器摆位的场景；要追求万级流畅，应换方案 A。
- 2.x 移植常见坑：右/上边缘 anchor 修正遗漏 → "列表最右一列不显示"（anchor 修正属于虚拟列表移植 bug 重灾区，见 references/01 §2）。
- `requestAnimationFrame` 各端其实有 adapter 提供，真正问题是生命周期归属（组件销毁要手动停），不是可用性（见 references/02 §7）。

## 方案 C：分层渲染（降 DC）

### 动机

item 内 Label 与 Sprite 材质不同 → 每个 item 断一次批，DC ≈ 2×N；分层后同类渲染组件归到同层连续提交，实测 DC 可从 33 降到 3。

### 机制（代理）

1. 原节点 A 上的渲染组件**销毁**，A 变纯数据节点；
2. 复制一个只含渲染组件的代理节点 B 挂到 renderLayer（同类型共用一层）；
3. 每帧（sync 间隔）从 A 的**世界矩阵**同步 B 的 pos/rot/scale/size/anchor/opacity（沿父链累计到 renderLayer 为止），矩阵相等则跳过；
4. 业务代码持有 Proxy 包装的渲染组件，`sprite.spriteFrame = x` 照写不误；
5. 层内排序：合成排序键（renderZIndex + sIndex*0.01 + 祖先叠加）写入节点排序键，脏时 rAF 里 sort children——这是 3.x 无节点 zIndex 的替代实现。

### 已知限制

- 父/祖节点旋转 + scaleX≠scaleY 时代理表现不一致（世界矩阵分解的固有限制）；
- Label 尺寸同步要再等一帧（二次 rAF hack）；
- **每个代理一条 rAF 循环**（自调度）——item 数上百后回调开销可观，接手改造时应合并为单一驱动；
- 分层节点必须仍在同一 Mask 子树内，否则逃逸裁剪；
- cell 循环利用仅支持单行/单列；
- 换代节点用 `instantiate` 后手工清子组件（整拷贝会出问题）。

### 替代路径

- 3.8.7+ 官方 `Sorting2D` 组件承接了该需求（sortingLayer/sortingOrder），可直接用；
- 3.8.6 想要同等效果只有代理方案或 UIStaticBatch（见 references/02 §6）。

## 从功能完整的第三方实现借鉴时的通用注意点

（以下与具体某个开源/付费实现的命名无关，是可复用的落地经验）

- **单文件巨石**要按需拆用：滚动器 + 虚拟化 + 刷新 + 分页 + 嵌套全挤在一个文件里时，只摘需要的模块，别整体搬。
- **初始化打印日志**要删：完整实现常在初始化时打印槽位/调试日志，真机上是纯损耗，上线前清掉。
- **脆实现勿照抄**：如"先 `active=false` → 布局 → `active=true`"依赖同帧渲染不可见的闪烁窗口，属脆弱技巧，正常应激活后再排版。
- **自绘滚动的代价**：放弃引擎 ScrollView 生态（ScrollBar 关联、编辑器配置），迁移成本要评估；若既要引擎生态又要虚拟化，优先基于引擎 ScrollView 的方案 A。

## 选型结论（写给选型纠结的人）

| 需求 | 建议 |
|---|---|
| 万级数据、流畅甩动、可控成本 | A（本技能 examples 实现） |
| 几百条、想沿用编辑器摆位、快速上线 | B（LoopList 思路，但把 AABB 检测换成索引数学更好） |
| DC 高（item 多材质混排） | A/B 之上叠 C；3.8.7+ 直接 Sorting2D |
| 既要引擎 ScrollView 生态又要虚拟化 | 本技能 examples（基于引擎 ScrollView 的 A 方案） |
| 聊天列表（贴底、异步高度） | A + 不等高闭环（references/01 §8） |
